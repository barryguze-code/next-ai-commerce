# Next AI Commerce v0.5.2 - Secure form hotfix

## Fixed

- Inline vendor creation no longer returns HTTP 403.
- Receiving start, additional document upload, discrepancy, vendor directory, account catalogue, catalogue import, and vendor-price forms now consistently carry Spring Security CSRF protection.
- Security remains enabled; the fix injects the valid session token instead of weakening request protection.

## Regression protection

- A template-wide test now fails whenever a new POST form is added without a Thymeleaf-secured action or explicit CSRF token.
- A request-level security test confirms vendor creation rejects missing tokens and succeeds with the correct token.
- A rendered-page test confirms the browser receives the hidden CSRF field.

- Previous checkpoint: tag `v0.5.1` at commit `b595891`.
