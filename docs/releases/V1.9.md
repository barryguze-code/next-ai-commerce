# 1.9 — Catalogue identity safeguards and workspace corrections

Status: implementation and verification in progress; not deployed.

The release prevents new ambiguous supplier-code bindings within an account and vendor/DC. Import previews explain conflicts, approval rechecks under the existing catalogue lock, manual offer writes reject competing products, and ambiguous invoice lookups require review. A known barcode cannot silently repoint an existing account item to another global product. Price history for the same item and separate vendor/account identities remain supported.

Existing conflicting records, mappings, stock and historical imports are preserved. This release does not claim to restore Ibcore's historical Folios association. Folios recovery and the existing Muesli code342934 conflict need verified source records and a separately reviewed data diff; no automatic merge, re-import or data repair is included.

Mapping labels distinguish Vendor item code from Account SKU and explain displayed barcode matches. Shared thumbnails clip only imagery, picture menus use content height, and Actions labels align left. The prior catalogue-table sorting, tab priorities and Inventory Ledger links are included. Changed assets have canonical1.9.0 cache URLs while unchanged assets retain their release versions.

Verification and release identity are recorded in the current STATUS; local evidence remains private under `.local/catalogue-incident-1-9-20261025/`. Exact candidate CI, independent review, fresh recoverable minor-release backup and actual rendered application verification remain release gates. No schema migration is introduced. Rollback uses the retained1.8.0 application/configuration; restoring catalogue data is a separate incident decision.
