# Next AI Commerce v0.5.4 - Warehouse receiving table

## Receiving workspace

- Replaced stacked receiving cards with one searchable HTML table and one compact row per product.
- Added product title, brand, item identity, and Amazon MAIN-image support without blocking receiving while images load.
- Aligned case, pack, each, expiration, condition, and Receive controls across every row.
- Added distinct pending, partial, complete, discrepancy, and over-shipped row colors in light and dark themes.
- Preserved a horizontally scrollable, sticky-product layout for small screens and warehouse tablets.

## Receiving rules

- Units per case now defaults to `1` unless the uploaded document detects a case pack.
- Existing untouched draft lines are repaired to the source-document pack when the migration runs; already received history is never rewritten.
- Short shipped, damaged, mispicked, soon-to-expire, and expired quantities remain outside sellable inventory and create vendor-credit records.
- Over-shipped entry separates the expected units at normal landed cost from only the extra units at zero cost.
- Inventory-ledger posting remains idempotent for both normally costed units and zero-cost overage units.

## Amazon images

- Listing reports retain an image URL when Amazon supplies one.
- A throttled Catalog Items API worker fills missing official MAIN images, prioritizing products in open receiving sessions.
- Image lookup failures never block receiving and are retried safely.
