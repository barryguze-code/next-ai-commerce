# v1.6.1 — FBM inventory publication fairness

- Pending stock changes no longer wait behind routine checks of already-confirmed zero-stock listings.
- Overdue work is processed oldest-first after two minutes, preventing repeated zero-stock retries from indefinitely starving restocks. Fresh zero-stock changes retain priority.
- Every active account is planned each cycle, with round-robin publication across accounts under the existing shared request budget.
- Failed inventory requests report the HTTP status and whether submission or verification failed, without exposing Amazon response bodies or credentials.

Order freshness, active-connection restrictions, shelf-life/hold rules, transaction locks, revision checks, and Amazon read-back verification remain enforced. No ledger quantities are rewritten by this release. Accepted submissions are not treated as confirmed inventory.

Operational rollout: enable the existing live publisher for all currently active production Amazon connections following the user's explicit approval. Preserve the nonlocal-write requirement and disabled legacy publisher. Verify each store's reconciliation and publication results after restart; unresolved Amazon errors remain visible rather than being labelled successful.
