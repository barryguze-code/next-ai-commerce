# v1.2.1 — Receiving closure and inventory pictures

## Changes
- Final receiving closure accepts historical undated receipts that have already been posted to the inventory ledger. Required expiration dates are still enforced before posting previously unrecorded stock.
- Available Inventory details provide an explicit Upload picture / Change picture button using the existing account-scoped image upload and access checks.
- Regression coverage keeps distinct item codes separate when their expiration dates match.

## Deployment and local development
No database migration is required. Local development and the release branch must point to the same verified release revision after deployment.

Eclipse: refresh the project, then run `Production - Deployment dashboard.launch` as an External Tool. This opens GitHub Actions. To redeploy published production code, choose Run workflow and select `release/v1.0.0`. This does not publish uncommitted local changes. To release new code, review and commit it, update the patch version and release notes, and push the release branch; its automated tests run before AWS deployment. Existing automatic backup and rollback protections remain enabled.

Deployment success is recorded separately in GitHub Actions; this document does not itself assert that the release is live.
