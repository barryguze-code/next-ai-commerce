# v1.3.3 — Shelf-life discounts and Orders ledger links

The production-only shelf-sale worker manages `discounted_price`, never `our_price` or quantity. It is restricted to the explicitly approved The Keto Storehouse connection. Local excludes the worker and disables all Amazon writes. An account switch in the sale-plan dialog starts disabled; enable it in production after deployment checks. Turning it off reconciles and removes managed discounts, rather than abandoning them.

Eligibility uses unreserved batch stock, mapping component quantities, shelf-life cutoff, configured start/end window, overrides and explicit SKU targets. Inventory publication must already be confirmed with positive quantity. The default percentage comes from the shelf policy (10% initially). A discount ends when qualifying stock is exhausted/reserved, held, outside its window, unmapped, or disabled. Cancellation can restore eligibility after reservations release.

Before writes, read Amazon's current offer. Preserve unknown promotions and flag a conflict. Store intended ownership before sending; verify accepted changes through a subsequent read. Retry unconfirmed work with bounded backoff. Every schedule has a finite end date; rollback or outage cannot leave an unlimited sale. Amazon propagation and storefront promotional presentation remain asynchronous. No storefront strike-through guarantee.

The queue makes at most one SKU's read/write sequence per two-second tick, skips inactive items without API calls and fairly revisits due work. Status and errors are retained per SKU, with transition audit events. Settings and publications are tenant-isolated. Migration V79 is additive and does not alter inventory or receipt records.

Orders mapped item-code links resolve through the selected account/connection mapping to an exact catalogue item. The ledger retains that item scope during search and paging, with a Show all items link.

Release checks include worker safety tests, isolated PostgreSQL migration/eligibility/reservation tests, exact-item ledger filtering, template/security tests and the standard CI browser suite. Enable only after the verified artifact is healthy in production; review conflicts/retries before considering publishing complete.
