# Version 0.6.1 — Live order stream

Released: 2026-08-30

## User experience

- Orders are grouped by Amazon marketplace day, newest day and newest order first.
- A quiet 30-second check updates the reusable order widget only when synchronized data changes.
- The page does not refresh while the user is interacting with a field or button.
- Newly synchronized orders appear at the top and trigger a short, non-blocking arrival notice.
- Every order shows its operational state, order total, and a transparent pending profit state.
- Unmapped live orders expose a direct **Map SKU** action using the first actually-unmapped SKU.
- **Buy Shipping** is visible but disabled and labelled **Coming soon**; no inactive control can mutate data.
- Historical orders remain visibly reporting-only and cannot affect inventory.

## Architecture

- The stream uses normalized `purchase_marketplace_date`, preserving the date shown by Seller Central.
- Stream changes are detected from order identity, fulfillment state, mapping count, and reservation state.
- The `orderStream` Thymeleaf fragment is reusable by the future Overview without duplicating status logic.
- Order state continues to come from the v0.6.0 reconciliation and reservation engine.

## Verification

- All 56 project tests pass; one optional parser fixture test remains skipped.
- A dedicated rendering test covers day grouping, live state, mapping, Buy Shipping, and pending profit.
