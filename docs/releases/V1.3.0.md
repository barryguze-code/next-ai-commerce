# v1.3.0 — release candidate

## User-facing changes

- Consistent operational table, picture-editing, mapping, collaboration and action controls.
- Account-scoped tagged smart filters, dynamic dates and compact filtered totals.
- Shared catalogue-item inventory fan-out to mapped FBM SKUs, multipacks and bundles.
- Durable publication queue, priority zero updates, verification/retries and a sync status page.
- Individual unresolved-order checks without a purchase-age cutoff. A missing order is not
  a cancellation. Overdue/missing checks retain reservations and expose review warnings.
- Confirmed cancellation releases are logged without adding physical stock. Stale responses
  cannot overwrite a newer cancellation. Packed stock is not automatically returned.

## Migration and release status

Migrations 74–77 add smart filters, shared picture overrides, the inventory publication outbox,
and unresolved-order status checks. No local business data or credentials are copied to production.

The complete clean local Java build passed: 264 tests, zero failures/errors, one intentionally
skipped test. The 41 JavaScript checks have 23 passes and 18 browser-launch failures caused by
the macOS sandbox (Mach-port permission denied). Run the full browser suite in CI before release.

**Production deployment and live publishing are blocked, not approved by these test results.**
Review and test the existing partial-shipment reservation/accounting path before activation.
Its current active-reservation lifecycle and availability-status predicate do not handle every
partial-shipment/cancellation combination safely. No broad availability predicate change was
made. The user has been asked whether to include this narrowly scoped fix in the release.

The deployment workflow targets v1.3.0 but keeps its existing release-branch trigger and all
test gates. The production deployment script still preserves existing publishing settings;
no production inventory activation has been added or performed.

## Required rollout after the remaining gate passes

1. Confirm the authorized seller/account/marketplace scope and current production revision.
2. Obtain green Java and browser CI on the exact commit; review migration checks and backup.
3. Merge the tested development head into the production release branch (never bypass CI).
4. Verify the server-side backup and health checks performed by the existing deployment.
5. Enable unresolved-order checks and the inventory publisher explicitly in production,
   with legacy listing inventory actions disabled. Local Amazon writes remain disabled.
6. Wait for a successful post-startup order reconciliation. The publisher refuses to send
   without a fresh completed order window or while order-import jobs remain unfinished.
7. Verify a small known set of zero/positive quantity submissions against Amazon before
   expanding to all approved mapped FBM SKUs. Never infer confirmation from ACCEPTED alone.
8. On failure, disable publishing first; restore the application/configuration using the
   retained rollback artifact. Application rollback does not undo quantities already sent
   to Amazon or revert database migrations. Reconcile affected SKUs explicitly.

Development continues from the v1.3.0 candidate; no production version/tag is asserted until
the protected rollout completes and deployed revision, schema and Amazon quantities are verified.
